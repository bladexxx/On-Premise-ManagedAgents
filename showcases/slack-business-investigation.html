INTEGRATIONS · EVIDENCE

Slack Business Investigation

A guided example of a question moving from a team conversation through a managed Session and configured MCP tools, then returning with traceable evidence.

Illustrative guided simulation. This page describes a product scenario using synthetic demo data. It does not connect to a live Slack workspace, Open Atlas service, MCP endpoint, customer environment, or OMA deployment.

THE FLOW

How the story unfolds.

01

Ask in Slack

A user asks a business question in a workspace. The request is routed to an OMA Agent through a configured integration.

02

Create a Session

OMA records the request in a durable Session event log and runs the Agent with its saved configuration.

03

Gather evidence

The Agent calls only the MCP tools configured for it. In this example, the source is represented as Open Atlas.

04

Review and respond

The Agent prepares an answer with evidence references, and the integration posts the result back to the conversation.

What this illustrates

  • An integration can start managed Agent work without making the messaging platform the system of record.
  • Session events make the request, tool activity, and final response inspectable.
  • MCP access is configured at the Agent boundary; the scenario does not imply broad or automatic access.

Operator considerations

  • Configure the Slack integration and MCP endpoint in your own deployment before expecting this workflow to run.
  • Use Vault-backed outbound credentials where supported, with destination and tool access configured for your environment.
  • Review the returned evidence and apply your organization’s approval rules before acting on consequential findings.
