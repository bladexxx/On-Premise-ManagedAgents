On-Premise Edition · API & SDK Reference

Build applications on OMA with a first-class independent SDK.

Use @openma/sdk for OMA application and platform APIs. Anthropic SDKs remain optional for compatible wire endpoints; they are not a replacement for OMA-native capabilities.

main-node onlyOMA SDK betaTypeScript normative surface

SDK Reference Scope

This is an independent OMA SDK reference. The TypeScript package is the normative typed surface for stable application and platform-management APIs, while raw access remains available for lower-frequency stable endpoints.

@openma/sdk

Application integration

Agents, Sessions, Environments, Apps, Files, Skills, Memory Stores, Dreams and Webhooks, including lifecycle, resources and SSE helpers.

OMA platform SDK

Native management

Vaults, Model Cards, API Keys, Analytics, Schedules, Workflow Runs and Evaluation Plans are first-class OMA SDK resources.

Explicit boundary

Supported raw escape hatch

Use oma.raw(method, path, init) for stable endpoints without a dedicated wrapper. Worker protocols, callbacks and debug routes remain outside the SDK.

Language guidance.TypeScript is the current normative OMA SDK. Python and Go clients are not synchronized OMA SDKs; use HTTP or an Anthropic SDK only for compatible wire endpoints.
Compatibility is not substitution.Anthropic SDKs share selected runtime conventions with OMA, but cannot represent the full OMA platform contract.

Authentication & Base URL

Create an OMA API key in the active Workspace. Point the official client at the OMA server root. Do not append /v1 to baseURL.

Ready

Initialize client

Anthropic({ apiKey, baseURL })

API KEY x-api-key
apiKeystring

OMA API key. It resolves the active Workspace / tenant context.

baseURLstring

OMA root, for example https://oma.company.example.

Client setup
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: process.env.OMA_API_KEY,
  baseURL: "https://oma.company.example",
});
from anthropic import Anthropic
import os

client = Anthropic(
    api_key=os.environ["OMA_API_KEY"],
    base_url="https://oma.company.example",
)
client := anthropic.NewClient(
  option.WithAPIKey(os.Getenv("OMA_API_KEY")),
  option.WithBaseURL("https://oma.company.example"),
)
export OMA_BASE_URL="https://oma.company.example"
export OMA_API_KEY="oma_..."

curl "$OMA_BASE_URL/v1/agents" \
  -H "x-api-key: $OMA_API_KEY"

Stream Session Events

client.beta.sessions.events.stream(sessionId)

GET /v1/sessions/:id/events/stream
Server-Sent EventsSSE

OMA emits named SSE events and defaults to Managed Agents compatible event types. A turn finishes at session.status_idle.

Read an Agent turn
const stream = await client.beta.sessions.events.stream("sess_...");
for await (const event of stream) {
  if (event.type === "agent.message") console.log(event.content);
  if (event.type === "session.status_idle") break;
}
for event in client.beta.sessions.events.stream("sess_..."):
    if event.type == "agent.message": print(event.content)
    if event.type == "session.status_idle": break
stream := client.Beta.Sessions.Events.Stream(ctx, "sess_...")
for stream.Next() { fmt.Println(stream.Current().Type) }

Applications, Webhooks and Evaluations

Applications group Agent integrations. Webhook subscriptions deliver selected Session events and may filter by Application and Agent IDs. Eval Runs are OMA Native APIs because a Batch compares multiple Agent configurations over the same task set.

DomainEndpointImportant behavior
Applications/v1/appsWorkspace-scoped application identity and Agent grouping.
Webhooks/v1/webhook_subscriptionsEvent types, endpoint, app/agent filters, delivery inspection and retry.
Eval Runs/v1/evals/runsterminate interrupts active Sessions and preserves evidence; delete is destructive and can include Sessions.

Model Cards and Azure OpenAI-compatible gateways

Model Cards keep provider, deployment/model ID, base URL and credentials together. Probe a card before assigning it to an Agent.

POST /v1/model_cards/probe
{
  "provider": "azure-openai-compatible",
  "base_url": "https://hostname/ai-gateway/api/v1/ai/azure/default",
  "model_id": "gpt-5.6-luna",
  "api_key": "..."
}

OMA constructs the Azure deployment route /openai/deployments/<model>/chat/completions?api-version=2024-10-21 and uses the api-key header. A probe 404 usually indicates that a deployment URL was supplied instead of the gateway root.

OpenShell and OpenSandbox execution

External workers publish sandbox_home_dir, sandbox_work_dir, sandbox_skills_dir and output support. OMA resolves file, Skill and workspace mounts from those capabilities; callers must not assume /sandbox or /mnt/session. Reset the Environment running binding after changing image, policy or worker paths.

Known Limits & Integration Guidance

Pin your SDK version.Compatibility is tested against a declared SDK version, not latest. Upgrade only after the OMA compatibility test matrix approves it.
  • Keep OMA base URLs and API keys in environment configuration, not source code.
  • Use { id, version } for production Sessions and evaluation workflows.
  • Use OMA Native APIs for workspace, membership and organization administration.
  • Do not assume all APIs visible in Anthropic documentation are available in On-Prem OMA.

认证与 Base URL

SDK 使用 x-api-key，Node 20、Bun、Deno、浏览器和 Cloudflare Workers 均可运行。

import { OpenMA } from "@openma/sdk";
const oma = new OpenMA({
  baseUrl: process.env.OMA_API_URL,
  apiKey: process.env.OMA_API_KEY,
});

PowerShell 请求请使用 Invoke-RestMethod -Headers @{"x-api-key"=$env:OMA_API_KEY}；不要把 /v1 重复拼到 SDK 的 root URL。

创建 Agent

model 可为字符串或带 speed 的对象；Agent 可绑定 Skills、MCP、callable_agents、Model Card、aux model 与 harness。

const agent = await oma.agents.create({
  name: "Researcher",
  model: "azure-gpt-o4-mini",
  system: "Answer with cited facts.",
  harness: "strands",
  skills: [{ skill_id: "skill_xxx", type: "prompt" }],
  mcp_servers: [{ name: "atlas", type: "http", url: "https://mcp.example/mcp" }],
});

创建 Session 与事件

const session = await oma.sessions.create({
  agent: { id: agent.id, version: agent.version },
  environment_id: "env_xxx",
});
await oma.sessions.sendMessage(session.id, "请检查输入文件");
for await (const event of oma.sessions.tail(session.id)) {
  if (event.type === "agent.message") console.log(event.content);
  if (event.type === "session.status_idle") break;
}

同一个 Session 的 turn 按顺序处理；客户端应等待 idle，或明确发送 interrupt。

资源、Environment 与 Sandbox

文件、GitHub、Memory Store 和 Vault 通过 Session resources 关联。OpenShell/OpenSandbox worker 会上报 sandbox_home_dir、sandbox_work_dir、sandbox_skills_dir 和 outputs 能力；客户端不要写死 /sandbox 或 /mnt/session。Worker 变更 image、policy 或工作目录后，需要 reset running binding。

事件、错误与版本建议

  • 使用 SSE /v1/sessions/:id/events/stream 实时接收事件，也可 JSON polling。
  • 保存 Agent 的 id + version，保证生产和 Eval 可复现。
  • 遇到 OpenMAError 时检查 status、body 和 raw。
  • terminate 会中断活动 Session 并保留证据；delete 会删除 Eval 数据，可选择同步删除关联 Sessions。
  • SDK 版本应锁定；以仓库当前类型导出为准，不要自动假设官方 SDK 的新资源已兼容。
