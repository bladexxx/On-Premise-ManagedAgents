ON-PREMISE · INSTALLATION

Install and operate OMA

OMA is distributed as versioned Linux deployment bundles and GHCR container images. Use the bundle and exact image tags from the same release so the server, Vault service, and sandbox worker stay compatible.

Release availability

Download links become active when the first public release is published. Until then, this page describes the intended installation flow; do not use placeholder image tags.

Open GitHub Releases ↗

Requirements

  • Linux x86_64 host with Docker Engine and the Docker Compose plugin.
  • Outbound access to GHCR and the model provider you configure.
  • A stable HTTPS URL and persistent storage for OMA data.
  • For isolated Agent tools, a separately configured OpenSandbox or OpenShell service and a matching sandbox-worker release.

First install

1. Download and verify the release bundle

Choose one release and download its oma-deployment-*.tar.gz plus the matching SHA-256 file. Verify the archive before extraction.

sha256sum -c oma-deployment-<version>.tar.gz.sha256
tar -xzf oma-deployment-<version>.tar.gz
cd oma-deployment-<version>

2. Set local secrets and URL

Copy the included environment template, set strong secrets, and restrict access to the resulting file. Do not commit it or place credentials in the public repository.

cp .env.example .env
chmod 600 .env
$EDITOR .env

Set the required model credential, BETTER_AUTH_SECRET, PLATFORM_ROOT_SECRET, and PUBLIC_BASE_URL. Back up the root secret securely; existing encrypted credentials depend on it.

3. Pull the version-pinned images and start OMA

Use the Compose file included in the release bundle. It references the matching image versions.

docker compose -f docker-compose.deployment.yml pull
docker compose -f docker-compose.deployment.yml up -d
docker compose -f docker-compose.deployment.yml ps
curl --fail http://127.0.0.1:8787/health

4. Put HTTPS in front of the Console

Configure your approved reverse proxy and DNS. Keep the application port private to the host or internal network, and set PUBLIC_BASE_URL to the browser-facing HTTPS origin.

5. Add an isolated sandbox worker when needed

The deployment archive includes a separately packaged worker for supported isolated runtimes. Follow the bundled release guide and use the worker package and server images from the same version.

Quick Start local execution and an isolated Environment have different trust boundaries. Follow the user guide and the release notes to choose a safe runtime.

Upgrade and rollback

Download the next version into a separate directory, back up the persistent data directory, and preserve the existing local environment configuration while updating image tags from the new bundle. Pull and restart using that version's Compose file. A database migration may not be reversible; restore the matching data backup when rolling back.

Release contents

Each published release should include the deployment bundle, checksum, standalone sandbox-worker archive and checksum, exact image references, release notes, and license/third-party notices. GHCR packages must be set to public before users can pull without authentication.

For product workflows and configuration, continue with the OMA user guide. For application integration, use the SDK reference.
